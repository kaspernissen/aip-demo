What the slide is for

The thesis line, set like slide 3 so the room hears the callback. It is a statement, not an explanation; everything it rests on has been shown. Its three verbs each map to something concrete:

  • Draw it in the platform: identity (SPIRE), reach (Linkerd + NetworkPolicy), capability (agentgateway, policy service, flag), keystone (Kyverno). Not in the prompt.
  • Make it the default: deny by default everywhere. payments-mcp's Linkerd Server is accessPolicy: deny; the agents' egress allows only the gateway; the policy service denies unknown callers and levels; the guardrail is failClosed; the flag's committed default is assisted (€0).
  • Let the rings hold it: each layer assumes the one before it failed. Going around the gateway hits Linkerd; a valid passport still meets CEL; a passing CEL still meets the policy service; and the agent can't edit any of them.

The theory behind it

Plain words. We don't ask a microservice to promise it won't read another team's database; we don't give it the credentials. The same applies to agents, with more reason: their control loop is a model, which follows instructions most of the time, not all of the time. "Secure by default" and "least privilege" are old ideas; the slide argues they are sufficient for agents if applied at the platform layer.

Why defaults matter more for agents. Authority accumulates (slide 7): a tool added for one workflow stays for all. With a deny-by-default platform, every new capability is an explicit, reviewable grant. With allow-by-default, every gap is an unreviewed grant the model may discover at run time.
