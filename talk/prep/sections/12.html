So what does this ask us to build? Integration and rigor. Not invention.

[gesture across the top row, left to right]

Workload identity for every agent: SPIFFE and SPIRE, who is acting. Reach enforced on that identity: Linkerd, plus plain Kubernetes network policy, what it can reach. Authorization on every call at the tool boundary: agentgateway, what it may call.

[bottom row]

A live autonomy level per identity: an OpenFeature flag, how far it may go today. The agent kept out of its own guardrails: Kyverno, at admission. And Git as the only way to change any of it.

These are the exact projects in the demo Kasper runs in a few minutes. Almost all of them are CNCF; agentgateway sits in the Linux Foundation's Agentic AI Foundation.

What's genuinely new is small: agent identity and limits as declarative objects, and per-tool authorization for agent protocols like MCP. A thin new layer on a deep, stable foundation.

Each one is a production-grade project today.

Let's start at the core: who is acting.

What the slide is for

This is the bridge from the model (the Safe Operating Model's rings, slide 11) to the tools. The audience has just seen abstract rings; here they get one project per job, with the job in four or five words. The point to land is that none of this needs a new platform: bounding an agent uses the same identity, network and admission machinery we already run for microservices. "Not invention" is the claim; the next seven slides back it with config.

Each card maps to a ring and to a later slide: SPIFFE/SPIRE is the core (13, 14), Linkerd is Ring 1 (15), agentgateway is Ring 2 (16, 17), OpenFeature is the second half of Ring 2 (18), Kyverno is the keystone (19). Git has no slide of its own; it is the answer to the keystone's question "then who may change it?".

The theory behind it

Plain words. Think of a building. Identity is the badge, reach is which corridors lead where, capability is what the badge opens once you're at a door, the flag is today's clearance level, and the keystone is that nobody can print their own badge or rewrite the clearance list. Git is the paper trail for every change to the rules.

Why separate jobs. Each layer assumes the one before it can fail. A gateway rule is worthless if a pod can walk around the gateway (that's why reach exists); a reach rule keyed on a name is worthless if anyone can claim the name (that's why identity is the core); and all of them are worthless if the agent can edit them (the keystone). This is defence in depth, applied to an agent.

Policy enforcement point vs decision point. The cards mix two roles. agentgateway, Linkerd, NetworkPolicy and Kyverno enforce: they sit in the path and block. The decision service and the flag decide: they answer "may this caller do this, today?". Keeping those apart is what lets one rule change without touching the proxies.

Git, honestly. Northstar has no GitOps controller. The cluster is applied by scripts/setup-kind.sh from the repo, and the keystone's denial message says "Authority changes go through a reviewed commit". In production that sentence is enforced by Argo CD or Flux pulling from a protected branch, with the platform's own deploy identity as the only writer the keystone lets through.

Alternatives

  • Identity: projected ServiceAccount tokens (no extra system, Kubernetes-only, no attestation beyond the API server), cloud workload identity (IRSA, GKE Workload Identity), cert-manager's csi-driver-spiffe.
  • Reach: Istio or Cilium instead of Linkerd; Cilium also gives DNS-aware egress (toFQDNs) and flow logs.
  • Gateway: Agent Router (formerly Envoy AI Gateway), Kong AI Gateway, IBM ContextForge, LiteLLM.
  • Flags: any OpenFeature provider (LaunchDarkly, Flagsmith, Unleash, GO Feature Flag) behind the same SDK call.
  • Admission: Kubernetes ValidatingAdmissionPolicy, OPA Gatekeeper, Kubewarden.

The rings don't care which you pick. That's the slide's real message: the tooling is an implementation detail.

If someone asks

Is agentgateway CNCF?
No. It was donated to the Linux Foundation in August 2025 and joined the Agentic AI Foundation (AAIF) on 4 June 2026. MCP and A2A are in AAIF too.
"Production-grade" for Linkerd, when OSS ships edge releases only?
True: there has been no open-source stable release since February 2024; stable builds come from vendors. The project is CNCF graduated and the policy CRDs used here are long-standing. Say this plainly if a regulated-industry listener asks.
Why not one tool that does it all?
Because each layer must hold if the one beside it fails. One tool is one misconfiguration away from no guardrail.
