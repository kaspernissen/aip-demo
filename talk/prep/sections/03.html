Let's start with one sentence.

An autonomous agent will do exactly what its tools let it do, and no more.

That sounds reassuring. It isn't. Because the set of things its tools let it do is almost never the set anyone deliberately chose.

What the slide is for

This is the opening claim, and the whole talk hangs off it. Two ideas in two lines. First: an agent's real authority is defined by its capabilities (tools, credentials, network reach), not by its instructions. Second: those capabilities usually grow by accident. The third line ("someone will ask what it did") sets up slide 4, the auditor's questions. The final slides (39 and 40) return to this sentence: "the boundary will not come from the agent."

The theory behind it

Plain words. Think of a new employee given a master key "just for today". They may only ever open the doors they need, but what they can open is every door. Security is about what is possible, not what is intended.

Precisely. An LLM-based agent is a loop: the model reads context, picks a tool, the runtime executes that tool with whatever credentials the process holds, and the result feeds the next step. The model does not execute anything itself; the tool binding does. So the upper bound of an agent's behaviour is the union of everything its tool bindings and credentials allow. The model's choices only select a path inside that set, and that selection is probabilistic (slide 8).

The security community has names for this. OWASP lists Excessive Agency (LLM06) in its Top 10 for LLM applications and has a separate Agentic Top 10 (ASI01–ASI10); the recommended principle is "least agency": the smallest set of actions an agent needs. The classic failure where a privileged component is tricked into acting for someone who should not have that power is the confused deputy.

How Northstar makes the sentence true in the safe direction

In the demo, the settlement agent can call execute_payment, but only through agentgateway, and only with its SPIFFE identity. Its tools let it ask for a payment of any amount; the platform decides. agents/settlement-agent/settlement.py has no spending limit, deliberately; the check lives in the Policy Decision Service.
