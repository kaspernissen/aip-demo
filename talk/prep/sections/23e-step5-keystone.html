Last question, and William asked it on slide 18: if one value decides this much, who may change it? Could the agent just give itself more authority?

[Part 1: Forbidden.]

Here the agent tries to edit its own flag, as its own service account. RBAC says no. That's the first line.

[Part 2: the over-grant, "auth can-i" says yes.]

Now I make the mistake every platform team eventually makes: I grant the agent permission to patch that flag. RBAC would now allow it.

[Part 3: DENIED by Kyverno.]

Same patch. Kyverno says no, and names the policy. Then the mistake is taken back, and the flag is unchanged.

"Authority changes go through a reviewed commit, never through the agent."

[Back to the deck: "What you just saw".]

What the audience sees (trimmed)

$ scripts/demo keystone

KEYSTONE  the agent can never edit what constrains it
  acting as        system:serviceaccount:northstar-agents:settlement-agent
  flag now         autonomous

1  The agent tries to edit its own autonomy flag
  $ kubectl --as=system:serviceaccount:northstar-agents:settlement-agent \
      -n northstar-platform patch featureflag/northstar-autonomy --type=json -p '[…targeting/if/1…]'
    Error from server (Forbidden): … cannot get resource "featureflags" in API group
      "core.openfeature.dev" in the namespace "northstar-platform"
  -> [RBAC says no]  That is the first line.

2  Someone makes a mistake: the agent is over-granted patch on that one flag
  $ kubectl apply -f deploy/demo/keystone-overgrant.yaml
    role.rbac.authorization.k8s.io/keystone-demo-overgrant created
    rolebinding.rbac.authorization.k8s.io/keystone-demo-overgrant created
  $ kubectl --as=…:settlement-agent auth can-i patch featureflag/northstar-autonomy
  -> yes   RBAC would now allow it

3  The same patch again. RBAC allows it. Kyverno does not.
    admission webhook "vpol.validate.kyverno.svc-fail-finegrained-agents-cannot-edit-their-own-authority"
    denied the request: Policy agents-cannot-edit-their-own-authority failed:
    [DENIED]: agent identity '…:settlement-agent' may not change the objects that define its own
      authority (FeatureFlag/northstar-autonomy).
    Authority changes go through a reviewed commit, never a runtime decision by the agent.

4  Take the mistake back       keystone-demo-overgrant deleted
5  What does the flag resolve to now?
  -> settlement-agent resolves: [autonomous]   (unchanged)

The agent could not edit what constrains it, even with the grant.
  • Part 1: plain RBAC. The agent's service account has no rights on FeatureFlags.
  • Part 3: the Kyverno ValidatingPolicy from slide 19 matches on the requester (any service account in northstar-agents or northstar-tools), not on what RBAC allows. So a wrong RoleBinding cannot open the door.
  • Parts 4 and 5: the over-grant is removed and flagd still resolves the same value. Nothing changed.
