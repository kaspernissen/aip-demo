GUARD  who may call the payment tools, and by which road
--------------------------------------------------------
1  No identity
  A caller with no SPIRE identity asks the gateway what tools exist.
  $ POST gateway/mcp  tools/list   (no token)
  -> HTTP 401  authentication failure: no bearer token found
  And a direct call to the payment tool:
  $ POST gateway/mcp  tools/call execute_payment   (no token)
  -> HTTP 401  nothing forwarded
2  Around the gateway
  From inside claims-agent: no SVID, no business at the tool.
  $ GET   settlement-agent:9002   (the one peer it may call: the control)
  -> REACHED  200  (the network works)
  $ POST  payments-mcp:8000/mcp  initialize, straight to the tool, 8s timeout
  -> DROPPED  no answer, no 401. The packet never arrived.
3  With settlement-agent's identity
  SPIRE mints the same JWT-SVID settlement-agent holds (not shown).
  $ spire-server jwt mint   sub=settlement-agent  aud=agentgateway
    …
  $ POST gateway/mcp  tools/list   (bearer SVID)
  -> HTTP 200  tools settlement-agent may call:
       propose_payment Propose a payment for a claim. Records an intent; moves no money.
       execute_payment Execute a previously proposed payment.
       refuse_payment  Record why a payout was refused, beside the payout.
       get_payment     Read back what the ledger recorded for a payment.
  Listed is not permitted: every call is decided, one by one.
guard holds: no identity, no road, one way in.

KEYSTONE  the agent can never edit what constrains it
-----------------------------------------------------
  acting as        system:serviceaccount:northstar-agents:settlement-agent

  $ kubectl --as=settlement-agent patch featureflag/northstar-autonomy  -> autonomous
    Error from server (Forbidden): featureflags.core.openfeature.dev "northstar-autonomy" is

    "featureflags" in API group "core.openfeature.dev" in the namespace "northstar-platform"
  -> RBAC says no  That is the first line.
2  Someone makes a mistake: the agent is over-granted patch on that one flag
  $ kubectl apply -f deploy/demo/keystone-overgrant.yaml

    rolebinding.rbac.authorization.k8s.io/keystone-demo-overgrant created
  $ kubectl auth can-i patch featureflag/northstar-autonomy --as=settlement-agent
  -> yes   RBAC would now allow it
3  The same patch again. RBAC allows it. Kyverno does not.
  $ kubectl --as=settlement-agent patch featureflag/northstar-autonomy  -> autonomous
    Error from server: admission webhook
    "vpol.validate.kyverno.svc-fail-finegrained-agents-cannot-edit-their-own-authority" denied the
    request: Policy agents-cannot-edit-their-own-authority failed: DENIED: agent identity
    'system:serviceaccount:northstar-agents:settlement-agent' may not change the objects that define
    its own authority (FeatureFlag/northstar-autonomy). Authority changes go through a reviewed
    commit, never a runtime decision by the agent.
  -> DENIED by Kyverno, naming the policy. The second line.
4  Take the mistake back
  …
  -> settlement-agent resolves: assisted
The agent could not edit what constrains it, even with the grant.
