# M1.2 "Intelligence" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace settlement-agent's hardcoded decision stub with a real PydanticAI agent on Claude that chooses and calls the MCP payment tools itself, so that `gen_ai.*` spans appear inside the single trace M1.1 already proved.

**Architecture:** `settlement.py` becomes a PydanticAI `Agent` with two registered tools that delegate to the existing, already-verified `mcp_tools.PaymentsTools`. The model decides *whether and how* to pay; the MCP call path, its `params._meta` trace-context injection and its error handling are unchanged. The executor stops orchestrating propose→execute and instead runs the agent, then assembles its reply from what `payments-api` actually recorded rather than from anything the model said.

**Tech Stack:** Python 3.13, `pydantic-ai-slim[anthropic]==2.41.0`, Claude Sonnet 5, existing `mcp==1.9.4` + `a2a-sdk[telemetry]==0.3.7`, OpenTelemetry SDK 1.44.0, pytest.

**Spec:** `docs/superpowers/specs/2026-09-07-northstar-m1-connected-design.md` (§10 "M1.2 — Intelligence", §8 telemetry contract, §"Model configuration", §11 testing)

**Verified research this plan rests on:** `.superpowers/research/m1.2-pydanticai-verification.md`. Every PydanticAI API name, signature and default in this plan was read from installed source or exercised live in a scratch venv. **Do not substitute a different API shape from memory** — two plausible-looking APIs (`Agent(instrument=True)`, `mcp.tool_name`) provably do not exist.

## Global Constraints

- **Never invent telemetry.** Use what the frameworks emit; verify per component; instrument only our own code. Where a convention gap exists, record it in `docs/upstream-findings.md` — do not paper over it with a bespoke attribute. This is the project's governing rule.
- **Never print, echo, log or commit a secret value.** `.env` is git-ignored. Report credentials as `SET` / `EMPTY` only. This includes shell traces, test output and Kubernetes manifests.
- **Python 3.13** (`uv venv --python 3.13`; `python:3.13-slim` base image).
- **Images via the local registry** as `localhost:5001/northstar/<component>:dev` with `imagePullPolicy: Always`. Never `kind load`.
- **Pin every dependency to an exact version.** No version ranges. No dependency carrying a known CVE or advisory — check before pinning.
- **Trace lookups in tests are by injected trace ID**, never by searching for an operation name or URL path. Search-based lookup returned a 14-minute-old trace twice during M1.1.
- **MCP trace context travels in JSON-RPC `params._meta`** (SEP-414, unprefixed `traceparent`/`tracestate`/`baggage`), never an HTTP header.
- **A brief-defect fix must carry a regression test that asserts substance.** A fix without a test that fails before it is not done.
- **Do not file, comment on, or write anything to any upstream issue or repository.** Reading public trackers is expected.
- **Never touch the `capybara` cluster or the shared `kind-registry`.** Never run `scripts/teardown.sh`.
- **The single-trace property is the acceptance gate.** One trace, one browser-owned root, zero orphans. If a change breaks it, the change is wrong — not the assertion.

## The design decision this plan encodes

Research established that PydanticAI's own `MCPToolset` **does** inject `traceparent` into `params._meta` correctly. It is not used here anyway, for two reasons:

1. **A hard, unsatisfiable pin conflict.** `pydantic-ai[mcp]` requires `fastmcp-slim[client]<5,>=3.3.0`, which requires `mcp<3.0.0,>=2.0.0`. This service pins `mcp==1.9.4`, which `mcp_tools.py`'s low-level `send_request` propagation depends on. Adopting `MCPToolset` therefore means an `mcp` major-version bump plus re-verification of the whole chain — real, scoped work, but not M1.2's work.
2. **M1.2's entire value is diagnostic isolation.** The spec says it plainly: *"Any failure is now unambiguously agent logic, never propagation."* Swapping the MCP client library in the same milestone that introduces a language model destroys exactly that property.

So: **the model chooses, our verified code calls.** `mcp_tools.py` is not modified by this plan.

**Deferred, recorded here so it is not lost:** bumping `mcp` to 2.x would let `mcp_tools.py` use the merged upstream `call_tool(meta=...)` (see `docs/upstream-findings.md` Finding 4), align settlement-agent with `payments-mcp`'s already-resolved `mcp==2.1.1`, and enable `MCPToolset` with real `tools/list` discovery — which would surface `execute_payment`'s `destructiveHint` annotation to the model. Good work for M1.3 or immediately pre-M2. Not now.

### A deliberate divergence from the spec, so no reviewer flags it as a gap

The spec's §10 says M1.2 replaces "stub bodie**s** with PydanticAI agent**s**" — plural. This plan converts **only settlement-agent**. `claims-agent` deliberately stays a deterministic router until M1.3.

Reason: `claims-agent` has exactly one permitted delegate today, so LLM-driven routing there is a fake choice — the model would "decide" to do the only thing available. Routing becomes a real decision when `policy-agent` and `assessment-agent` exist in M1.3. Meanwhile settlement-agent already has a genuine multi-step tool decision, which is the narrative beat M1.2 exists to earn.

`claims-agent` is therefore out of scope here, and its `delegation.py` allow-list must not be touched.

### The rule that makes this demo honest

**The model narrates. The system of record states the amounts.** The reply the customer sees takes `amount`, `currency`, `status` and `paymentId` from what `payments-api` actually recorded, and only `narrative` from the model. A model that describes a €4,000 payment cannot cause a reply claiming €4,000 was paid when the ledger says €6,200.

Note carefully what this does **not** do: it does not stop the model *proposing* a different amount. In M1 nothing checks that — deliberately. That is the ungoverned hole M2's Policy Decision Service fills with its Mutate outcome. If during implementation the model proves unreliable about the amount, **record it as a finding; do not clamp it.** A hardcoded clamp would quietly re-hardcode the decision this milestone exists to remove, and would delete the demo's motivation for M2.

"""Settlement agent behaviour, with no API key and no network.

FunctionModel drives an exact tool-call script; TestModel exercises the
happy path generically. Neither touches Anthropic.
"""
from __future__ import annotations

import pytest
from pydantic_ai.messages import ModelResponse, TextPart, ToolCallPart
from pydantic_ai.models.function import FunctionModel

from mcp_tools import ToolCallError
from settlement import decide_settlement, settlement_agent

CLAIM = {"claimId": "CLM-1842", "amount": 6200, "currency": "EUR"}


class FakePayments:
    """Stands in for PaymentsTools. Records calls; returns payments-api shapes."""

    def __init__(self, *, execute_raises: Exception | None = None) -> None:
        self.calls: list[tuple] = []
        self._execute_raises = execute_raises

    async def propose(self, claim_id, amount, currency="EUR"):
        self.calls.append(("propose", claim_id, amount, currency))
        return {
            "paymentId": "PAY-000001",
            "claimId": claim_id,
            "amount": float(amount),
            "currency": currency,
            "status": "PROPOSED",
        }

    async def execute(self, payment_id):
        self.calls.append(("execute", payment_id))
        if self._execute_raises:
            raise self._execute_raises
        return {
            "paymentId": payment_id,
            "claimId": "CLM-1842",
            "amount": 6200.0,
            "currency": "EUR",
            "status": "EXECUTED",
        }


def _script(*, amount: float = 6200.0, narrative: str = "Settled in full."):
    """A FunctionModel that proposes, then executes, then narrates."""
    state = {"step": 0}

    def fake_model(messages, info):
        state["step"] += 1
        if state["step"] == 1:
            return ModelResponse(
                parts=[ToolCallPart("propose_payment", {"amount": amount, "currency": "EUR"})]
            )
        if state["step"] == 2:
            return ModelResponse(
                parts=[ToolCallPart("execute_payment", {"payment_id": "PAY-000001"})]
            )
        return ModelResponse(parts=[TextPart(content=narrative)])

    return FunctionModel(fake_model)


async def _run(claim, payments, model):
    with settlement_agent.override(model=model):
        return await decide_settlement(claim, payments)


@pytest.mark.asyncio
async def test_model_calls_propose_then_execute_in_that_order():
    payments = FakePayments()
    await _run(CLAIM, payments, _script())
    assert [c[0] for c in payments.calls] == ["propose", "execute"]


@pytest.mark.asyncio
async def test_reply_amount_comes_from_the_ledger_not_from_the_model():
    """The model narrates; payments-api states the amount.

    The scripted model proposes 4000 while FakePayments.execute reports 6200.
    The returned amount must be 6200 — what was actually recorded.
    """
    payments = FakePayments()
    result = await _run(CLAIM, payments, _script(amount=4000.0, narrative="Paid 4000."))
    assert result["amount"] == 6200.0
    assert result["status"] == "EXECUTED"
    assert result["paymentId"] == "PAY-000001"


@pytest.mark.asyncio
async def test_narrative_comes_from_the_model():
    payments = FakePayments()
    result = await _run(CLAIM, payments, _script(narrative="Rear-end collision, covered."))
    assert "Rear-end collision" in result["narrative"]


@pytest.mark.asyncio
async def test_tool_call_error_propagates_to_the_caller():
    """mcp_tools.ToolCallError must not be swallowed into a narrative.

    a2a-sdk turns a raised exception into a JSON-RPC error carrying str(exc);
    a model apologising in prose instead would hide a failed payment.
    """
    payments = FakePayments(execute_raises=ToolCallError("payment already executed"))
    with pytest.raises(ToolCallError, match="already executed"):
        await _run(CLAIM, payments, _script())


@pytest.mark.asyncio
async def test_missing_claim_id_is_rejected_before_the_model_runs():
    payments = FakePayments()
    with pytest.raises(ValueError, match="claimId"):
        await _run({"amount": 100}, payments, _script())

@pytest.mark.asyncio

    with pytest.raises(ValueError, match="amount"):

- [ ] **Step 3: Write `settlement.py`**

```python
"""Settlement decision — a real model call as of M1.2.

In M1.1 this was a hardcoded function. The model now decides whether and how
to pay, by calling the MCP payment tools itself.

Two deliberate properties:

  * The MCP call path is unchanged. `mcp_tools.PaymentsTools` still makes
    every call, so the verified `params._meta` trace-context propagation and
    error handling are exactly what M1.1 proved. The model chooses; our code
    calls.
  * The model narrates; `payments-api` states the amounts. The reply's
    amount/currency/status/paymentId come from what the ledger recorded, never
    from model output. See the plan's "the rule that makes this demo honest".

There is no €5,000 check here, and that is the point: M1 is ungoverned on
purpose. The model can propose any amount and nothing stops it. That hole is
what M2's Policy Decision Service fills.
"""
from __future__ import annotations

import os
from dataclasses import dataclass, field
from typing import Any

from pydantic import BaseModel, Field
from pydantic_ai import Agent, RunContext

DEFAULT_MODEL = "anthropic:claude-sonnet-5"


@dataclass
class PaymentRecord:
    """What the ledger actually recorded, as opposed to what the model said."""

    proposed: dict[str, Any] | None = None
    executed: dict[str, Any] | None = None


@dataclass
class SettlementDeps:
    payments: Any  # mcp_tools.PaymentsTools, or a test double
    claim: dict[str, Any]
    record: PaymentRecord = field(default_factory=PaymentRecord)


class SettlementNarrative(BaseModel):
    """The only thing the model is trusted to produce."""

    narrative: str = Field(description="One or two sentences a claimant would read.")


settlement_agent = Agent(
    os.environ.get("NORTHSTAR_SETTLEMENT_MODEL", DEFAULT_MODEL),
    deps_type=SettlementDeps,
    output_type=SettlementNarrative,
    # Defer model resolution to first run. Without this, constructing the
    # Agent at import time can require ANTHROPIC_API_KEY to be present, which
    # would break the token-free unit suite (it imports this module but always
    # runs under `settlement_agent.override(model=...)` and never resolves the
    # real model). Verified parameter on Agent.__init__ at 2.41.0.
    defer_model_check=True,
    instructions=(
        "You settle motor insurance claims for Northstar Insurance.\n"
        "You are given a claim that has already been assessed as covered.\n"
        "Settle it by calling propose_payment with the assessed amount, then "
        "execute_payment with the paymentId you get back.\n"
        "Then reply with a short narrative for the claimant.\n"
        "Settle the assessed amount. Do not round it, discount it or "
        "renegotiate it. Do not state amounts in your narrative."
    ),
)


@settlement_agent.tool
async def propose_payment(
    ctx: RunContext[SettlementDeps], amount: float, currency: str = "EUR"
) -> dict[str, Any]:
    """Propose a payment against this claim. Returns the payment, including its paymentId."""
    result = await ctx.deps.payments.propose(ctx.deps.claim["claimId"], amount, currency)
    ctx.deps.record.proposed = result
    return result


@settlement_agent.tool
async def execute_payment(ctx: RunContext[SettlementDeps], payment_id: str) -> dict[str, Any]:
    """Execute a proposed payment. This moves money and cannot be undone."""
    result = await ctx.deps.payments.execute(payment_id)
    ctx.deps.record.executed = result
    return result


def _validate(claim: dict[str, Any]) -> tuple[str, float, str]:
    """Validate before spending tokens. Contract preserved from M1.1."""
    claim_id = claim.get("claimId")
    if not claim_id:
        raise ValueError("claimId is required")

    amount = claim.get("amount")
    if amount is None:
        raise ValueError("amount is required")
    if amount < 0:
        raise ValueError("amount must not be negative")

    return claim_id, float(amount), claim.get("currency") or "EUR"


async def decide_settlement(claim: dict[str, Any], payments: Any) -> dict[str, Any]:
    """Settle a claim. Raises ValueError on a malformed claim, before any model call.

    Lets mcp_tools.ToolCallError propagate: a2a-sdk turns it into a JSON-RPC
    error carrying str(exc). A model apologising in prose would hide a
    failed payment.
    """
    claim_id, amount, currency = _validate(claim)

    deps = SettlementDeps(
        payments=payments,
        claim={"claimId": claim_id, "amount": amount, "currency": currency},
    )

    result = await settlement_agent.run(
        f"Claim {claim_id} is assessed as covered for {amount:.0f} {currency}. Settle it.",
        deps=deps,
    )

    executed = deps.record.executed
    if executed is None:
        raise RuntimeError(
            f"claim {claim_id}: the model finished without executing a payment; "
            f"proposed={deps.record.proposed!r}"
        )

    return {
        "amount": executed["amount"],
        "currency": executed["currency"],
        "status": executed["status"],
        "paymentId": executed["paymentId"],
        "narrative": result.output.narrative,
    }
```

2. **The baggage attach at intake stays.** `otel_context.attach(set_claim_id(...))` is the only place `northstar.claim.id` enters baggage.
