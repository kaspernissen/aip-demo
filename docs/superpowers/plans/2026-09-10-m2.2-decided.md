# M2.2 "Decided" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The platform refuses the €6,200 payout on caller identity plus amount, the model narrates the refusal without retrying, and the whole thing is one trace.

**Architecture:** agentgateway calls an external Policy Decision Service over gRPC on every MCP `tools/call`, using its `mcpGuardrails` remote-processor hook (the `ExtMCP` proto). The PDS answers permit/deny from the caller's SPIFFE ID, the tool name and the requested amount, and emits its own `policy.decision` span into the same trace. `settlement-agent` and `payments-mcp` contain no policy logic; the only application change is a branch in `mcp_tools.py` that turns a denial into a terminal, explicitly non-retryable tool result.

**Tech Stack:** agentgateway v1.5.0 (`mcpGuardrails` + `ext_mcp.proto`), Python 3.13 + grpcio for the PDS, OpenTelemetry Python SDK, SPIRE 1.15.3 (JWT-SVID), Cilium 1.20.1 (`toFQDNs`), PydanticAI 2.41.0, kind.

**Spec:** `docs/superpowers/specs/2026-09-09-northstar-m2-governed-design.md`

**Branch:** `m2.2-decided`, already created from `main` @ `m2.1-verified`, carrying one commit (`d17309c`) that closed the gateway-bypass hole with a `CiliumNetworkPolicy`.

## What is already established, so no task re-derives it

Read from agentgateway's source at tag **v1.5.0**, not from its documentation site (the spec records the docs site as thin and unreliable; the repo is authoritative).

**The config key is `mcpGuardrails`, not `extMcp`.** It is a route/backend policy and a sibling of `mcpAuthorization`. From `crates/agentgateway/src/types/local.rs:1882`: *"MCP policies (mcpAuthorization, mcpGuardrails) apply to the full target set and belong on the route or `mcp.policies`."*

Shape, from `crates/agentgateway/src/mcp/guardrails/mod.rs`:

```
McpGuardrails { processors: Vec<Processor> }
Processor      { methods: HashMap<String, Phase>, #[serde(flatten)] kind: ProcessorKind }
ProcessorKind  = Remote(Remote)                      // serde tag = "kind"
Remote         { <SimpleBackendReferenceWithPolicies flattened>,
                 failureMode: FailureMode,
                 metadata: HashMap<String, cel::Expression>,
                 requestHeaders: HeaderFilter }
Phase          = Off | Request | Response | Full      // default Off
FailureMode    = FailOpen | FailClosed
```

**`failureMode` must be set explicitly to `failClosed`.** `FailureMode` derives `Default` with `FailOpen` first, so the default is fail-open: if the PDS is unreachable, every payment is permitted and the demo silently loses its entire point. `client.rs` confirms the branch — `FailureMode::FailOpen => Outcome::Pass`. The gRPC call carries a 10-second default timeout (`BackendRequestTimeout(Duration::from_secs(10))`).

**The proto** is `crates/protos/proto/ext_mcp.proto`, package `agentgateway.dev.ext_mcp`:

```
service ExtMcp {
  rpc CheckRequest (McpRequest)  returns (McpRequestResult);   // unary
  rpc CheckResponse(McpResponse) returns (McpResponseResult);  // unary
}
McpRequest        { repeated string service_names = 1; string method = 2;
                    google.protobuf.Struct metadata_context = 3;
                    optional bytes mcp_request = 4;            // JSON-RPC params
                    repeated McpHeader headers = 5; }
McpRequestResult  { oneof result { Pass pass; bytes mutated; AuthorizationError error; }
                    HeaderMutation header_mutation = 4;
                    google.protobuf.Struct metadata = 5; }
AuthorizationError { Code code = 1;                            // UNKNOWN | PERMISSION_DENIED
                                                               // | RESOURCE_EXHAUSTED | INVALID
                     string reason = 2;
                     optional bytes mcp_error = 3; }           // custom JSON-RPC error override
```

`AuthorizationError.mcp_error` is the mechanism for a structured denial: it lets the PDS supply the exact JSON-RPC error body the client receives, rather than accepting a generic one.

**There is no `examples/` directory for this.** The repo has `mcp-authorization` (the native CEL mechanism the spike used) but nothing for `mcpGuardrails`/ExtMCP, which is precisely why Task 1 exists.

**What remains genuinely unknown, and is Task 1's job:** the on-the-wire deny shape as the *client* sees it, and how the caller's SPIFFE ID reaches the PDS (via `metadata` CEL expressions, via forwarded `requestHeaders`, or both).

**A stale note in the spec, for the implementer's benefit:** §5 says the client is `mcp==1.9.4`. The tree is on `mcp==1.28.1` in `settlement-agent` (and `2.1.1` in `payments-mcp`). The spec's reasoning about transport exceptions still holds — `mcp` calls `raise_for_status()` before parsing, so a JSON-RPC error on a non-2xx status surfaces as `httpx.HTTPStatusError` inside an `anyio` `ExceptionGroup` — but do not trust the version number in that paragraph.

# platform/policy-decision-service/pds/rules.py
"""The policy, and nothing else.

Deliberately free of gRPC, OpenTelemetry and I/O so it can be exercised
exhaustively in microseconds. `server.py` adapts the wire format to this;
this module never learns what a wire is.
"""

from dataclasses import dataclass

# The rule shape the spec fixes, and the one M5 mutates:
#   "settlement-agent, at autonomy level `assisted`, may execute up to €6,000."
# Keyed by (SPIFFE ID, autonomy level) so the identity is structurally required
# rather than merely consulted.
EXECUTE_LIMITS: dict[tuple[str, str], float] = {
    ("spiffe://northstar.local/ns/northstar-agents/sa/settlement-agent",
     "assisted"): 6000.0,
    ("spiffe://northstar.local/ns/northstar-agents/sa/settlement-agent",
     "autonomous"): 1_000_000.0,
}

# Tools with no world-changing effect. Proposing is reversible; executing moves
# money. Only the latter is limited.
UNLIMITED_TOOLS = frozenset({"propose_payment"})
LIMITED_TOOLS = frozenset({"execute_payment"})


@dataclass(frozen=True)
class PolicyInput:
    caller: str | None
    tool: str
    amount: float | None
    currency: str
    autonomy_level: str


@dataclass(frozen=True)
class Decision:
    permit: bool
    reason: str
    rule: str
    limit: float | None = None
    # Always False. A denial the agent may retry is a denial it can sit on
    # stage retrying; see the spec's §5 hazard.
    retryable: bool = False


def decide(req: PolicyInput) -> Decision:
    if req.tool in UNLIMITED_TOOLS:
        return Decision(True, f"{req.tool} has no effect to authorise",
                        rule="unlimited_tool")

    if req.tool not in LIMITED_TOOLS:
        return Decision(False, f"unknown tool {req.tool!r}", rule="unknown_tool")

    limit = EXECUTE_LIMITS.get((req.caller or "", req.autonomy_level))
    if limit is None:
        return Decision(
            False,
            f"no execute allowance for caller {req.caller!r} at autonomy "
            f"level {req.autonomy_level!r}",
            rule="unknown_caller",
        )

    if req.amount is None:
        return Decision(False, "no amount present on an execute request",
                        rule="malformed_request", limit=limit)

    if req.amount > limit:
        return Decision(
            False,
            f"requested {req.amount:.0f} {req.currency} exceeds the "
            f"{limit:.0f} {req.currency} limit for this agent at autonomy "
            f"level {req.autonomy_level}",
            rule="settlement-agent.assisted.execute_limit",
            limit=limit,
        )

    return Decision(True, f"{req.amount:.0f} {req.currency} is within the "
                    f"{limit:.0f} {req.currency} limit",
                    rule="settlement-agent.assisted.execute_limit", limit=limit)
```

Note the deny rule name is `settlement-agent.assisted.execute_limit` for both the permit and the deny branch at the limited tool, because the same rule fired — only its outcome differs. The tests assert that name only on the deny path.

# platform/policy-decision-service/pds/identity.py
"""Recovering the caller's SPIFFE ID from an ExtMCP request.

The gateway has already verified the JWT-SVID's signature, issuer, audience
and expiry before it calls us -- that is what `jwtAuth` does, and re-verifying
here would duplicate it. What this module does is decide whether the value the
gateway passed us is an identity we recognise at all.
"""

TRUST_DOMAIN = "spiffe://northstar.local/"


def caller_spiffe_id(metadata: dict, headers: list) -> str | None:
    value = metadata.get("caller")
    if not isinstance(value, str):
        return None
    if not value.startswith(TRUST_DOMAIN):
        return None
    return value
```
