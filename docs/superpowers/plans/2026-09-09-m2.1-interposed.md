# M2.1 "Interposed" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a real proxy and real workload identity into the MCP path without breaking the single distributed trace, and prove that identity is load-bearing — all before any policy logic exists.

**Architecture:** A new kind cluster with Cilium as CNI replaces the stage-1 cluster (`disableDefaultCNI` is a create-time flag). agentgateway is deployed into `northstar-platform` and interposed between `settlement-agent` and `payments-mcp`, initially permitting everything. SPIRE issues JWT-SVIDs; `settlement-agent` presents one on every MCP call and the gateway verifies it, making the caller's SPIFFE ID available for policy that M2.2 will add.

**Tech Stack:** kind, Cilium (CNI), agentgateway v1.5.0 (Linux Foundation; Rust; MCP streamable HTTP), SPIFFE/SPIRE, existing stack — Python 3.13, PydanticAI 2.41.0, FastMCP 4.0.3, `mcp==1.28.1`, Go, OpenTelemetry, Jaeger.

**Spec:** `docs/superpowers/specs/2026-09-09-northstar-m2-governed-design.md`

**Predecessor:** `main` at tag `m1.2-verified`. Read `docs/architecture.md` and `docs/telemetry-contract.md` before starting.

## Global Constraints

- **No invented telemetry.** Copied verbatim from the user: *"You are not allowed to invent telemetry for the tools we are using. I want this to be as real as possible. Of course of our custom components, we can add custom telemetry, but we should use frameworks and output the real telemetry."* Every attribute name published in a doc must be measured from live output or cited to a line of installed source. Our own components may carry custom attributes; agentgateway's and SPIRE's spans are recorded as they actually appear.
- **Nothing goes upstream.** *"We haven't created an upstream repo yet. Let's just keep it local until we have something. Let's hold off on upstream for now. Note them down on a list with context, and what would needed to be fixed, and why, what the problem is etc."* `docs/upstream-findings.md` is that list. Nothing may be filed, commented on, or written to any upstream tracker or repository. Reading public trackers is fine and expected.
- **Content capture stays ON.** `NORTHSTAR_CAPTURE_CONTENT` defaults to `true`; the observability-versus-confidentiality trade-off stays recorded as OQ-1, unresolved.
- **Nothing floats.** Every dependency, chart and image pinned to an exact version. `agents/settlement-agent/tests/test_pins.py` enforces the ones that matter, reading `importlib.metadata` — **never** a requirements file. A pin file is not an installed tree.
- **No exact whole-trace span total may be published.** The trace is non-deterministic: the a2a-sdk's internal `dequeue_event` polling span was measured varying 10–16 across identically-shaped runs. Per-service unit-test count rows in `docs/telemetry-contract.md` *are* published and guarded by `tests/unit/test_telemetry_contract_counts.py`.
- **`.superpowers/` is git-ignored.** Docs cite workspace reports as labelled provenance only, never as openable files. In-tree runnable tests are the evidence.
- **Test runner is the root `.venv`** (`.venv/bin/python -m pytest tests/... -q`); service suites use their own venvs. `scripts/smoke-test.sh` is the authority on invocation.
- **Never delete, restart or reconfigure the `capybara` kind cluster or the shared `kind-registry`.** The `northstar` cluster IS recreated in Task 1 — that is this plan's one sanctioned cluster deletion, and only that cluster.
- **Never print, echo, `cat` or log `.env`.** Report secrets as SET/EMPTY only. Never `set -x` near secret handling.
- **Stray port-forwards:** find the PID with `lsof -nP -iTCP:<port> -sTCP:LISTEN` and kill only that PID. Never a blanket `pkill`.
- **Never install tooling into a service venv** — their contents are pinned and asserted. Use `uvx` or a throwaway venv in the scratchpad. Note `uvx pip-audit` reliably crashes on `ensurepip` on this machine (three reproductions); go straight to a scratchpad venv.
- **Cache hygiene after any temporary edit:** revert it, run `find . -name '__pycache__' -type d -prune -exec rm -rf {} +`, re-run, and confirm `git status --porcelain -uall` is clean. A stale `.pyc` once made a pin test report a version nobody had written.
- **`kubectl diff` cannot prove a revert** — it is a three-way merge against `last-applied-configuration`. Read values back with `jsonpath`.
- **A live end-to-end run spends real Anthropic tokens.** A bare `pytest tests/` is not free: `tests/e2e/test_settlement_agent_trace.py` and `tests/e2e/test_claims_chain_trace.py` each drive a live model-driven settlement. Prefer reading existing Jaeger traces; spend fresh runs when a claim needs one.

## The risk this plan is shaped around

M1.2 spent eight tasks establishing one property: **one trace, one browser-owned root, zero orphans, five services.** This plan puts a new CNI *underneath* that trace and a new proxy *inside* it. Either could break it.

So every infrastructure change is isolated and followed immediately by re-verifying the trace, before the next change is added. If the trace breaks, there is exactly one suspect. This is the same discipline that made M1.2's `mcp` 1.9.4 → 1.28.1 bump safe, and it is why no policy logic appears anywhere in this plan — a denial arriving in the same milestone as a CNI swap would give a failure two suspects.

## What the spike already settled — do not re-derive

From `.superpowers/spikes/2026-09-09-agentgateway-spike.md` (git-ignored; cited here as provenance, and the facts are restated in full so no task needs to open it):

- **The single trace survives agentgateway.** Measured in Jaeger with a faithful client, parent chain intact: `caller → agentgateway "tools/call" → agentgateway "tools/call payments-mcp_propose_payment" → payments-mcp "tools/call propose_payment" → payments-mcp "POST" → payments-api "POST /payments/propose"`.
- **Why it survives:** `HTTPXClientInstrumentor` is active in `settlement-agent` and `streamablehttp_client` runs on httpx, so MCP POSTs carry a `traceparent` **HTTP header** automatically — verified against an echo server, not inferred from docs. agentgateway reads that header. `mcp_tools.py`'s docstring saying *"Nothing is injected into HTTP headers by hand"* refers to **manual** injection only; do not read it as "no header is sent."
- **agentgateway v1.5.0**, Linux Foundation project (**not** CNCF), Rust, idle RSS **11.2 MiB**. Image `cr.agentgateway.dev/agentgateway:v1.5.0`. Serves MCP over streamable HTTP at `/mcp` and SSE at `/sse`.
- **Its documentation site is thin and unreliable; the repo's `examples/` directory matched real behaviour exactly.** Treat the repo as authoritative.
- **Two independent policy mechanisms exist**: native CEL `mcpAuthorization` (in-config, no external call) and `ExtMCP` (gRPC hook to an external service). **M2.2 uses `ExtMCP`.** This plan uses neither — it deploys the gateway permitting everything.
- **CEL context includes** `mcp.tool.name`, `jwt.*` claims from a verified JWT, and `source.spiffeId` for mTLS-verified callers.

## Task 4: SPIRE, and a JWT-SVID on every MCP call

**Files:**

**Interfaces:**
- Consumes: the gateway config from Task 2; the MCP client call site in `mcp_tools.py`.
- Produces:
  - `svid.py`: `async def fetch_jwt_svid(audience: str) -> str` — returns a JWT-SVID for the given audience, cached until 30s before expiry. Raises `SvidUnavailable` (defined in the same module) when the Workload API cannot be reached.
  - `mcp_tools.py` sends that token as an HTTP header on every MCP call.
  - The gateway verifies it and exposes the caller's SPIFFE ID to CEL. **M2.2's PDS consumes this identity** — it is the reason this task exists.

**Why JWT-SVID and not mTLS.** The spec permits either. mTLS would mean threading a SPIFFE TLS context through `streamablehttp_client`'s transport — real risk inside the one file the spec allows M2 to modify. A JWT-SVID keeps the identity genuinely SPIFFE-issued (a `spiffe://` subject, signed by SPIRE, verified via JWKS), costs one header, and the spike confirmed `jwt.*` claims are available to the gateway's CEL context. **Record mTLS as later hardening in `docs/architecture.md`**, with this reasoning, so the weaker bearer-token choice is visible rather than silent.
