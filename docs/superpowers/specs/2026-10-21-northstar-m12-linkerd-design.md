# Northstar M12 — Linkerd for reach — Design

**Status:** approved in direction by Kasper on 2026-10-20 ("we need to replace Cilium with Linkerd", at William's request); detailed design written 2026-10-21 by the orchestrator while Kasper was away, from the 2026-10-12 spike, the 2026-10-20 research notes and a 2026-10-21 inventory of the repo. Decisions Kasper has not seen are marked **(orchestrator ruling)**.

## 1. Why

William asked for Linkerd. He and Kasper are both Linkerd ambassadors, and the Safe Operating Model's Ring 1 ("What may it connect to?") is where a mesh belongs. The 2026-10-12 spike settled what Linkerd can and cannot carry here:

- **Ingress (who gets in): Linkerd does it better.** Authorization is by workload identity, at the destination proxy, and a refusal is an HTTP 403 (gRPC `PERMISSION_DENIED`) that is counted (`inbound_http_authz_deny_total`). Under Cilium a refusal is a silent drop that appears nowhere.
- **Egress (who gets out): Linkerd cannot do it alone.** `EgressNetwork` is namespace-wide, SNI-matched and bypassable by any pod that skips its proxy. So egress moves to core Kubernetes **NetworkPolicy**, enforced in the node by kindnet (kind >= 0.24 ships kube-network-policies, on by default). It works whether or not the workload cooperates with a proxy.
- **Trace: one trace, not fragmented.** The proxies join W3C context. M12 does **not** turn on proxy tracing **(orchestrator ruling)**: it would add about 140 proxy spans per run to every trace, and the MCP and ExtMCP proxy spans are dead-end siblings because those protocols carry context in the payload. The trace's shape stays exactly as M11 measured it, and the deny counter is the new evidence.

## 2. What changes

| | M11 (Cilium) | M12 (Linkerd + NetworkPolicy) |
|---|---|---|
| CNI | Cilium 1.20.1, `disableDefaultCNI` | kind's default kindnet, with NetworkPolicy |
| Ingress to payments-mcp, PDS | CiliumNetworkPolicy, by pod label, drop | Linkerd `Server` + `AuthorizationPolicy` + `MeshTLSAuthentication`, by identity (`agentgateway`'s SA), 403 |
| Who may call payments-api, and which routes | Cilium L7 `rules.http` on the **caller's egress** | Linkerd `HTTPRoute` + per-route `AuthorizationPolicy` on **payments-api's ingress**, by caller identity |
| The `/a2a/push` route on customer-ui | Cilium L7 on claims-agent's egress | Linkerd route policy on customer-ui's ingress: only claims-agent may POST `/a2a/push` |
| settlement-agent ingress | Cilium, claims-agent only | Linkerd, claims-agent's identity only |
| Model egress | `toFQDNs: api.anthropic.com` on settlement-agent | NetworkPolicy `ipBlock` 160.79.104.0/23 and 2607:6bc0::/48, TCP 443, settlement-agent only (Anthropic's published API range) |
| Everything else out of the agent pods | denied (Cilium default-deny) | denied (NetworkPolicy default-deny egress, per pod) |
| Kubelet probes | `fromEntities: host` | no network rule needed (ingress is Linkerd's); probe paths authorized where a Server has routes |
| Keystone | protects `cilium.io` policies | protects `networking.k8s.io` NetworkPolicies and `policy.linkerd.io` objects |

**Meshed workloads (orchestrator ruling):** the three app namespaces (`northstar-agents`, `northstar-tools`, `northstar-systems`) by namespace annotation, plus `agentgateway` and `policy-decision-service` by pod annotation. The platform namespace's other pods (Backstage, eval-scorer, flagd...) and every infrastructure namespace stay unmeshed: this milestone is about reach, not a mesh everywhere.

**Default inbound policy:** `all-unauthenticated` (Linkerd's default). Only ports that have a `Server` are restricted. A Server with no matching authorization denies.

## 3. What we lose, said plainly

- **Egress by name becomes egress by address range.** `toFQDNs` followed DNS; `ipBlock` follows Anthropic's published range, which "will not change without notice". Any other host in that /23 is also reachable.
- **No DNS-proxy evidence.** Under Cilium the test could see the DNS proxy port on settlement-agent only. There is no equivalent.
- **Egress enforcement is kind's.** kube-network-policies is the enforcement here; a production cluster needs a CNI that enforces NetworkPolicy. The policy objects are portable; the enforcement is not.
- **TCP connect no longer means reach.** A meshed pod's proxy accepts the TCP connection and then refuses the request. Every probe that asserted "connect timed out" must now assert on the HTTP status (ingress) or keep the timeout only where NetworkPolicy drops (egress).
- **More moving parts:** a proxy in each meshed pod, a control plane, a certificate chain (openssl, P-256, generated by `setup-kind.sh` into a git-ignored directory).
- **OSS Linkerd ships edge releases only** (no OSS stable since stable-2.14.10, 2024). We pin `edge-26.10.1`.

## 4. What we gain

- Refusals you can show: 403, `PERMISSION_DENIED`, a counter per policy.
- Reach keyed by the same identity (namespace/serviceaccount) SPIRE attests, not by pod labels anyone with a Deployment can set.
- mTLS between meshed workloads.
- The hostNetwork gap the spike flagged (Cilium's `fromEntities: host` let a host-network pod into payments-mcp and the PDS) closes: a host-network pod has no mesh identity.
- The beat William wanted, on a stage where both speakers are Linkerd ambassadors.

## 5. One identity, two credentials

A settlement-agent pod now holds two credentials for one identity (its namespace and service account): Linkerd's certificate (may it **connect**) and the SPIRE SVID (may it **call this tool**). They do not wrap each other: agentgateway still checks the SVID JWT in the request; Linkerd checks the TLS peer. The deck's identity slide says so in one line.

## 6. Out of scope

Proxy tracing; Linkerd's viz/jaeger extensions (deprecated); multicluster; egress through a Linkerd egress gateway; Prometheus scraping of proxy metrics (a follow-up: it needs pod discovery RBAC for the collector); any change to the money path (agentgateway, ExtMCP, PDS failClosed, the ceiling, the ledger).
