# **Held at 0.3.7 deliberately.** The newest installable release is 1.1.2
# (2026-07-22 on PyPI; the project's GitHub releases go to v1.1.4 but v1.1.3
# and v1.1.4 were never published to PyPI -- both /pypi/a2a-sdk/<v>/json
# return 404 -- so 1.1.2 is "latest" for anything that can be pinned). It was
# evaluated and NOT taken. Two reasons, both measured against the installed
# 1.1.2 rather than read off a changelog:
#
#   * The thing that would have justified the risk is not there.
#     docs/upstream-findings.md is precisely about this library not
#     extracting inbound trace context and its spans carrying no attributes.
#     At 1.1.2, `propagate`/`traceparent`/`TextMapPropagator` are still 0 hits
#     across the package, and all 17 instrumented modules still carry a bare
#     `@trace_class(kind=...)` with no `attributes=`. The StarletteInstrumentor
#     workaround is still required.
#   * 1.x is a protocol migration, not a bump. It implements A2A v1.0 with
#     v0.3 behind an opt-in compat layer: the JSON-RPC method is `SendMessage`
#     rather than `message/send` (this repo sends `message/send` from 13 files
#     in three languages), `a2a.types.AgentCard` is a protobuf message that
#     cannot parse this repo's own committed agent card, and
#     `a2a.server.apps.A2AStarletteApplication` -- what main.py builds and what
#     StarletteInstrumentor attaches to -- does not exist there.
#
# a2a.server.apps.A2AStarletteApplication requires starlette/sse-starlette to
# be importable, but a2a-sdk's telemetry extra doesn't declare them — only
# the separate http-server extra does. This service's venv has always had
# them, but only because mcp declares both as its own unconditional
# dependencies; that made this dependency accidental rather than declared
# (found while implementing claims-agent, which has no mcp dependency to mask
# the same gap — see agents/claims-agent/NOTES.md). Pinned explicitly here,
# at the exact versions already resolved via mcp, so this is a determinism
# fix, not a version bump.
